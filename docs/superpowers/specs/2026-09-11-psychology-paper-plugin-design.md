# Psychology Paper：心理学科学写作项目与 Codex Plugin 设计

## 文档状态

- 状态：设计及收口修订已由用户通过，进入实施计划阶段
- 日期：2026-09-11
- 项目名称：`psychology-paper`
- 目标：形成一个可放入 GitHub、可安装到 Codex、可在单篇心理学论文项目中长期使用的科学写作与投稿工作流
- 实施状态：本文件是设计规范，不代表 Plugin、Skills、脚本或测试已经实现

## 1. 项目目标

`psychology-paper` 面向心理学论文的规划、证据审查、期刊适配、写作、返修、数据复核和投稿准备。它不是一个包办所有工作的“大 Skill”，而是一个短路由器、多个职责单一的专业 Skill，以及每篇论文自己的最小项目状态。

项目解决五类反复出现的问题：

1. 在没有确定论文类型、证据强度和目标期刊前就直接重写全文。
2. 学位论文、旧手稿、当前投稿稿、原始数据和历史统计输出之间的权威关系不清。
3. 修改结果数字后，摘要、结果解释、讨论、图表和补充材料没有同步。
4. 每改一句话就重新读取、生成和保存整篇 Word，造成 Token 浪费和版本混乱。
5. 不同 Skill 各自重复读取全文、重新解释用户决定，导致口径漂移。

## 2. 核心设计原则

### 2.1 自适应路由

系统先理解用户实际要做什么，再决定是否启用完整项目流程。用户不需要使用固定术语。局部任务直接短路；全文修改、重新分析、返修和投稿进入项目模式。

### 2.2 用户确认是正式决定的唯一入口

- “先判断”“先讨论”表示只生成判断或候选，不修改。
- “通过”“采用你的”“按这个改”表示当前候选成为正式决定。
- “直接往原文件改”表示已确认内容获得本次写入授权，不表示允许扩大全文修改。
- “不改”“别管”表示当前建议退出执行清单。
- “先留着”表示问题进入有意暂留状态，普通轮次不重复提醒。

审查授权、重算授权、采用结果和写入文件是四种不同授权。

### 2.3 一个任务只有一个主模块

每轮必须确定一个 `PRIMARY_MODULE`。支持模块只接收当前问题的最小信息包，不能自行把局部任务扩大为全文工程。

### 2.4 渐进加载

采用 Nature Skills 中已验证的静态/动态分层思想：

- `SKILL.md` 只保存目的、关键约束和路由。
- `manifest.yaml` 声明任务轴和加载路径。
- `static/core/` 保存少量稳定规则。
- `static/fragments/` 保存按论文类型、设计、章节、语言或模式选择的规则。
- `references/` 只在复杂问题出现时读取。
- `.shared/` 保存多个模块真正共用的高风险规则，但不默认全部加载。

运行时不允许 Agent 直接拼接或猜测上述资源路径。各 Skill 只向插件根目录中的确定性资源加载器提交 Manifest 逻辑选择器；加载器以自身安装位置解析插件根目录，自动包含 `always_load`，并只返回本次明确选择的条件规则。加载器不得遍历目录、模糊匹配文件名或在失败后搜索整个仓库。默认单次返回上限为 12,000 字符，超出时不返回部分规则，而是要求缩小选择范围。

`manifest.yaml` 是逻辑选择器与资源路径的唯一权威定义。构建测试逐项验证所有登记资源存在且未越出插件根目录；正常安装版本不得出现声明资源缺失。运行时若仍发生缺失，视为插件完整性损坏并停止该插件调用，而不是跳过规则继续工作。

### 2.5 项目状态只保存已确认信息

项目不保存完整聊天记录、被否决的全文版本或 AI 的临时解释。长期保存的内容限于：当前权威文件、目标期刊、用户已通过的决定、正文采用的统计规格、正式分析脚本与输出位置、有意暂留问题和下一步任务。

### 2.6 定点补丁优先

以下规则为硬约束：

```text
PATCH_FIRST = true
FULL_REBUILD_ON_LOCAL_EDIT = false
AUTO_VERSIONED_COPY = false
FULL_RENDER_ONLY_AT_MILESTONE = true
```

一句话或一个段落的修改不重建整份 Word，不自动生成日期副本。只有图表、目录、分页、题注、交叉引用等版式敏感内容发生改变，或到达投稿里程碑时，才执行完整渲染和视觉检查。

“局部修改”只描述写入范围，不等于禁止检查影响范围。纯语法、拼写、标点和不改变语义的格式修改不读取全文。样本量、统计结果、构念名称、研究编号、假设、中心结论或其他可能跨章节传播的信息发生变化时，必须先执行影响扫描。影响扫描优先使用项目状态、术语账本、结构索引和全文检索定位候选位置；若这些信息不足以判断覆盖范围，可以读取相关章节乃至全文。该例外允许“读取以判断影响”，不授权重写全文。扫描只生成同步清单，用户确认修改范围后才执行定点补丁。

### 2.7 证据边界优先于漂亮叙事

系统必须区分观察事实、关联、预测、条件效应、实验操纵效应、机制解释、跨研究综合和外部推广。不通过尝试多种计分、样本或模型来追求显著；不把不同软件、不同样本或不同分析规格的参数拼在同一正文中。

## 4. 总路由器 `psychology-paper`

### 4.1 职责

总路由器只负责：

1. 识别任务、范围、语言、授权和项目模式。
2. 读取必要的项目状态。
3. 选择一个主模块和必要支持模块。
4. 管理用户确认门和停止条件。
5. 在用户通过后更新紧凑项目状态。

它不直接撰写章节、重算统计、检索文献或修改 Word。

### 4.2 路由维度

| 维度 | 取值示例 |
|---|---|
| 任务 | 诊断、期刊、证据、文献、写作、返修、投稿、统计、文档修改 |
| 范围 | 句子、段落、章节、全文、投稿里程碑 |
| 语言 | 中文、英文、中译英、双语核对 |
| 权限 | 只读、候选、已批准、允许写入 |
| 项目模式 | 轻量任务、长期论文项目 |

### 4.3 用户语言的自适应识别

路由器根据语义识别用户意图，不要求用户学习命令。例如：

- “先看看有没有问题”映射为只读诊断。
- “用 Excel 重新计算”映射为分析任务，但先核对研究设计和字段。
- “不要动数据，只改文字”冻结数字和统计口径。
- “只报告初筛拒稿问题”设置风险阈值为 R0–R1。
- “作为审稿人审一下”保持只读，不写入稿件。

### 4.4 范围升级与误判兜底

路由器先判断请求的表面范围，再判断内容是否具有跨章节传播性。以下变化即使用户只指向一句话，也不能直接送入文档修改：

- 样本量、排除人数、统计量、显著性或效应方向；
- 构念、操纵、测量、结果指标或研究编号的正式名称；
- 假设、中心发现、机制解释、边界条件或总体结论；
- 题目、摘要或章节总结中承担全文定位功能的表述；
- 权威数据、计分方式或分析来源。

这些请求先升级为 `change-impact audit`。系统依次使用项目状态和术语账本、对提取文本的关键词与结构检索、目标位置上下文读取、相关章节读取；只有前述方法不能可靠覆盖时才读取全文。无论读取范围多大，默认输出仍是影响位置清单，不自动扩大写入范围。

路由器不确定某项修改是否会改变证据含义时，优先转交 `evidence-audit`，不得直接交给 `document-patcher`。测试必须同时覆盖“局部任务未被过度升级”和“看似局部但实际跨章节的变化被正确升级”。

## 5. 专业模块

### 5.1 `journal-fit-style`

负责论文画像、期刊方向推荐、已有目标期刊的匹配评估，以及目标期刊行文组织风格学习。

无目标期刊时：

1. 建立 manuscript profile。
2. 判断心理学方向、论文类型、核心问题、贡献、证据类型、证据强度、读者、最强点和主要限制。
3. 提供进取、平衡和稳妥三档候选。
4. 每个候选默认轻量扫描 1–2 篇高度相近论文。
5. 询问用户更重视层级、匹配、速度、录用概率、费用和时间。

目标期刊确认后：

1. 核对官方 scope、article type、篇幅、匿名、伦理、数据、开放科学和格式要求。
2. 默认深度观察 2–3 篇高度相似的近期论文；只有风格冲突时才扩展。
3. 分开记录官方要求和从已发表论文观察到的风格。
4. 形成紧凑 `JOURNAL_PROFILE.md`。

期刊适配不能退化为模仿几篇文章的用词。真正匹配包括研究问题、目标读者、证据类型、贡献层级和叙事方式。

### 5.2 `evidence-audit`

只读审查心理学论文的构念、设计、测量、数据、分析、结果解释和跨章节一致性。

状态：

```text
ALIGNED
BOUNDED
CONDITIONAL
UNRESOLVED
CONTRADICTED
OUTSIDE_EVIDENCE
```

风险：

```text
R0 诚信、伦理或合规底线
R1 可能导致编辑初筛拒稿
R2 可能导致外审重大质疑、大修或拒稿
R3 普通修改
R4 可选优化
```

范围支持局部、章节、全文和变更范围审查。具体检查内容必须适配论文类型、研究设计和仪器/数据类型；调查研究不得机械套用实验操纵检查，质性研究不得套用定量统计一致性清单。

核心检查包括：

- 构念定义、操作化、测量和命名的一致性。
- 特质、状态、操纵、操纵检查和代理指标的区分。
- 横断面关联、纵向预测、实验因果和机制推断的边界。
- 自评、偏好、选择、任务表现和实际后果行为的准确命名。
- 样本量、排除、缺失、字段、自由度、统计量、效应量和置信区间的可见一致性。
- 主效应、交互、简单效应、边际简单效应和简单—简单效应的正确解释。
- 结果变化后的跨章节同步清单。

没有重算授权时只能标记“需要复核”，不能偷偷尝试多种分析规格。

### 5.3 `literature-map`

以论文论断为中心管理文献，不以“搜到多少篇”为目标。

每项正式文献记录：

- 书目信息和可点击 DOI；无 DOI 时记录出版社、数据库或机构稳定链接。
- 它支持论文的具体位置和具体论断。
- 核验层级：书目信息、摘要、全文。
- 支持关系：直接支持、间接支持、边界证据、相反证据或不支持。
- 用户是否确认采用。

文献检索任务本身即构成该范围内的检索授权，无需每篇再次征求许可。只有用户确认采用的文献进入正式 `LITERATURE_MAP.tsv` 和正文。候选文献未采用后不长期保存长篇摘要。

### 5.4 `manuscript-writing`

采用短路由器加按需章节规则，完整支持中文心理学论文、英文投稿稿和中译英。

路由轴包括：论文类型、研究设计、章节、语言、任务模式和目标期刊画像。章节规则覆盖题目、摘要、引言、假设、方法、结果、研究间过渡、讨论、局限和结论。

通用写作原则：

- 以问题—证据—推论递进代替模板化总—分—总。
- 内容逻辑优先于机械连接词。
- 先呈现证据和模式，再推导含义。
- 用正面事实陈述证据边界，避免无必要的防御性否定。
- 功能区分优先于简单的变量替代叙事。
- 讨论按理论构念整合跨研究证据，不按实验编号复述结果。
- 外部文献既用于支持结果，也用于解释差异和不一致。
- 不新增数据、统计、文献或未经确认的事实。

默认候选格式：

英文修改：英文原文 → 修改后英文 → 对应中文翻译。

中文修改：中文原文 → 修改后中文 → 必要说明。

中译英：中文原文 → 修改后英文 → 中文回译。

问题标注与正文分开，默认提供可复制的 TXT 内容。用户通过并授权后才交给文档修改模块。

### 5.5 `review-revision`

支持模拟审稿、老师/合作者意见、正式审稿意见、返修执行、回复信和返修审计。

固定流程为：

```text
判断意见是否成立
→ 向用户说明影响
→ 用户决定
→ 执行获准修改
→ 验证稿件、证据和回复是否一致
```

审稿意见是需要判断的来源文件，不能自动全部接受。用户只要求审稿时，流程停止在反馈阶段。回复信只描述实际完成的修改，不把计划或静态检查写成已完成验证。

### 5.6 `submission-check`

支持早期投稿准备、正式投稿前、系统上传、返修提交和校样阶段。

要求类型：

```text
REQUIRED
CONDITIONAL
RECOMMENDED
AUTHOR_PREFERENCE
```

检查状态：

```text
PASS
FAIL
NEEDS_AUTHOR
NOT_APPLICABLE
NOT_VERIFIED
PENDING_FIX
FIXED_NEEDS_RECHECK
```

检查包括期刊官方要求、匿名、伦理和知情同意声明、数据与代码声明、Title Page、正文、图表、补充材料、参考文献和上传文件。Cover Letter 作为独立投稿材料检查，不作为正文核心证据链的默认同步对象。

只有投稿里程碑执行全套检查，普通局部修改不触发整套投稿审查。

### 5.7 `analysis-adapter`

遵循以下顺序：

```text
研究设计
→ 数据字段
→ 计分
→ 样本
→ 模型
→ 软件
→ 结果
→ 正文同步
```

在读取数据后，系统必须主动与作者核对字段是否与实验设计匹配，包括但不限于：观察单位、条件编码、原始题目、复合得分、反向计分、缺失值、零值、排除状态、协变量、操纵、操纵检查、中介、调节和结果指标。还应主动询问是否存在未识别的重要字段或重复测量层级。

若无法从论文、方法、材料、预注册或作者说明重建设计，应索要实验设计，而不是根据列名猜测。

统计来源规则：

- 每项正文分析只能有一个 `AUTHORITATIVE` 来源。
- 可有一个 `VERIFICATION` 来源用于独立复核。
- 用户有原分析软件、语法和输出时优先复现原软件。
- 用户只有 Excel/CSV 且分析可透明重建时，优先建议 Python 或 R。
- SPSS PROCESS、Mplus、JASP、jamovi、Stata 等特有结果优先调用相应接口；没有接口时读取导出语法和结果。
- 第二种软件只检查一致性，不能从两套结果中选择更好看的参数。

系统必须记录正式软件、版本、数据、计分、样本、模型、估计方法、Bootstrap 设置和随机种子。用户决定采用正式结果后，才更新 `ANALYSIS_REGISTRY.md` 并生成跨章节同步清单。

### 5.8 `document-patcher`

首版支持 DOCX、TXT 和 Markdown 的定点修改；PDF 只读；电子表格和图形分别交由数据或图表工具处理。

该模块虽属于总体架构，但在阶段 1A 不启用写权限。只有期刊分析、证据审查和候选写作在只读真实任务中通过验收后，才在阶段 1B 实现并开放受控写入。

状态：

```text
NOT_APPLIED
PREPARED
PATCHED_UNVERIFIED
PATCHED_VISUAL_PENDING
DELIVERY_VERIFIED
PATCH_FAILED_NO_CHANGE
ROLLBACK_PENDING
ROLLED_BACK
ROLLBACK_FAILED
```

执行要求：

- 明确唯一权威目标文件。
- 使用唯一锚点定位修改位置。
- 修改前确认匹配数量和预期一致。
- 通过临时事务执行原子替换，成功后再覆盖目标。
- 写入前必须生成短期事务恢复材料；如果无法创建恢复材料，不得写入。
- 不生成自动日期副本。
- 不重新解释已经批准的文字。
- 局部修改只做结构和目标内容验证。
- 投稿里程碑才做完整渲染和视觉检查。

Word 或 OneDrive 锁定文件时，不强制关闭 Word，不结束用户程序，不创建绕过副本；报告状态并在文件可写后继续。

事务恢复材料不是新的用户稿件版本，不使用日期文件名，也不进入论文目录的正式稿件列表。它只在技术临时目录或 `.psychology-paper/.transactions/<transaction-id>/` 中保存到本次补丁验证完成。写入或结构验证失败时自动恢复原文件，并进入 `ROLLED_BACK`；若失败发生在替换目标文件之前，则进入 `PATCH_FAILED_NO_CHANGE`。用户在 `DELIVERY_VERIFIED` 前要求撤销时，可以使用该事务恢复材料回滚。完成交付验证后删除恢复材料。

若回滚时目标文件被 Word、OneDrive 或其他进程锁定，状态进入 `ROLLBACK_PENDING`：保留事务恢复材料，停止该文件的所有后续写入，报告锁定事实和仍待恢复的目标，待文件可写后继续同一次回滚。不得强制关闭 Word，也不得把 `ROLLBACK_PENDING` 报告为已经恢复。若恢复材料缺失、损坏，或解除锁定后仍因非暂时性错误无法恢复，状态进入 `ROLLBACK_FAILED`；保留现有文件和可用恢复材料，不继续修改，并请求用户决定人工恢复路径。只有原文件内容和结构均验证恢复后，才能进入 `ROLLED_BACK`。

如果科学判断在 `DELIVERY_VERIFIED` 后发生变化，不使用已经删除的技术快照暗中恢复旧稿，而是生成一项新的反向修改候选，经用户重新批准后定点修改。

### 6.1 决定、写入与一致性状态

```text
decision_status:
  DISCUSSION
  CANDIDATE
  APPROVED
  REJECTED
  INTENTIONAL_HOLD

write_permission:
  NOT_GRANTED
  WRITE_ALLOWED
```

批准决定、写入许可和补丁执行结果不是同一个状态轴。项目中分别记录 `decision_status`、`write_permission`、`patch_status`、`source_role`、`evidence_status`、`risk_level` 和 `check_status`，不计算或保存这些轴的笛卡尔积；只有当前任务需要的状态才出现。

`state-consistency.md` 是所有状态组合规则的单一权威来源，不允许总路由器、`validate_project.py` 和 `document-patcher` 分别手写或维护规则副本。该文件使用机器可读的 YAML frontmatter 保存规则编号、条件、阻断动作和适用组件，正文只解释规则语义，不重复另一套规则表。每条规则使用稳定编号，例如 `SC-001`。总路由器和 `document-patcher` 在运行时读取同一文件，`validate_project.py` 解析同一 YAML frontmatter；测试用例也按规则编号引用它。以后新增或修改非法组合只改这一文件，并由路径与行为测试确认三个组件读取的是同一版本。

至少拦截以下非法组合：

- `write_permission = WRITE_ALLOWED` 但 `decision_status` 不是 `APPROVED`；
- 写入目标仍标为 `RAW`，或标为 `HISTORICAL` 且未由用户明确重新指定为输出目标；
- `decision_status = REJECTED` 或 `INTENTIONAL_HOLD`，同时 `write_permission = WRITE_ALLOWED`；
- 科学论断为 `CONTRADICTED` 或 `OUTSIDE_EVIDENCE`，却在没有改写为探索性解释或明确证据边界的情况下请求写入；
- `patch_status = PATCHED_UNVERIFIED` 或 `PATCHED_VISUAL_PENDING`，但没有对应的补丁回执；
- `PATCHED_UNVERIFIED` 被报告为 `DELIVERY_VERIFIED`；
- `ROLLBACK_PENDING` 或 `ROLLBACK_FAILED` 时继续对同一文件执行新补丁，或将其报告为 `ROLLED_BACK`、`DELIVERY_VERIFIED`；
- 投稿检查仍为 `FAIL` 或 `NOT_VERIFIED`，却被记录为 `PASS`；
- 未解决的 R0 或 R1 问题存在时，系统把稿件标记为“投稿检查通过”。作者仍可决定投稿，但系统必须保持风险状态，不得给出通过结论。

用户批准表示允许采用某项选择，不会自动改变来源角色或提高证据等级。

### 6.3 多标签研究设计

论文类型、研究设计、数据单位和证据来源分别标记，避免把所有定量研究归为一类。行为实验、仪器研究、横断面问卷、纵向、被试内、被试间、因子设计、密集纵向、多层模型、心理生理和神经影像均可作为设计标签按需组合。

### 6.4 术语表

术语账本记录构念中英文名称、缩写、特质/状态层级、操纵名称、操纵检查、测量指标、结果指标和不可互换的近义词。它防止理论变量、操作方法和检查指标被写成同一概念。

### 6.5 变化同步

样本、计分、分析版本、显著性、变量命名、研究编号或中心论断变化后，进入 `change-impact audit`。实现路径为：先读取 `PROJECT.md`、存在时的 `ANALYSIS_REGISTRY.md` 和术语账本；再对提取后的正文执行标题、变量名、数字、统计模式和关键论断检索；然后读取命中位置的上下文。只有检索覆盖不足或变化涉及全文论证架构时才读取相关章节乃至全文。该流程生成可能受影响的位置清单，默认检查标题、摘要、关键词、引言末尾、假设、方法、结果、研究间过渡、总讨论、局限、结论、图表、图注和补充材料。用户决定修改范围后再写入；读取范围升级不等于写入范围升级。

```text

→ 正式分析
```

## 11. 项目初始化与验证脚本

### 11.1 `init_project.py`

仅负责在用户确认后创建 `.psychology-paper/PROJECT.md`。它不得移动或复制论文、修改数据、建立日期备份或扫描项目目录之外的文件。若状态已存在，应停止而不是覆盖。

### 11.2 `validate_project.py`

检查状态文件存在性、权威稿件路径、冲突的权威来源、被引用状态文件、遗留模板占位符和第 6.1 节定义的持久状态非法组合。非法组合不硬编码在脚本中；脚本解析 `.shared/core/state-consistency.md` 的 YAML frontmatter，并在规则文件缺失、格式无效或版本不兼容时停止验证。它不审查论文内容，也不自动修正状态。

## 13. Token 控制

软性预算：

| 文件或任务 | 建议范围 |
|---|---:|
| 总路由 `SKILL.md` | 800–1,500 Token |
| 专业模块 `SKILL.md` | 800–2,000 Token |
| `manifest.yaml` | 300–1,000 Token |
| 单个核心片段 | 300–1,200 Token |
| 单个章节或设计片段 | 500–1,500 Token |
| 单个深层参考 | 原则上不超过 3,000 Token |
| 日常 `PROJECT.md` | 500–1,200 Token |
| 单次模块默认规则加载 | 尽量不超过 3,000 Token |
| 单段“原文—修改稿—翻译”三联输出 | 2,000–6,000 Token |
| 单章“原文—修改稿—翻译”三联输出 | 8,000–18,000 Token |
| 全文三联输出 | 默认不一次生成；拆分章节，累计约 25,000–60,000 Token |

安全、数据来源和授权规则不为满足 Token 数字而删减。文件持续膨胀时优先拆分按需片段。

三联输出是写作模块最主要的输出成本。超过单章规模时按章节或小节分批处理；已经在权威文件中且用户只要求定点写入的原文，不为形式完整而重复输出整篇。预算用于提示分块和避免重复，不用于截断必要的证据说明。

## 14. 验证方案

### 14.1 结构验证

- 每个 Skill 运行官方 `quick_validate.py`。
- 整个 Plugin 运行 `validate_plugin.py`。
- 检查 frontmatter、名称、目录、必需字段和未完成占位符。

### 14.2 路径验证

- 所有 manifest 和 Markdown 引用必须存在。
- 不得存在无路由入口的孤立规则文件。
- 同一正式规则不得在多个文件重复维护。
- 每个 Skill 入口必须通过同一个确定性加载器读取内部规则，不得同时保留直接资源读取路径。
- 加载器从任意工作目录和中文路径运行时，均应解析到同一插件资源。
- 未知选择器、越界路径和缺失登记资源必须有限失败，不得触发目录遍历、相似文件回退或全仓库搜索。
- 单次加载超过默认字符预算时必须在输出前停止。

### 14.3 行为场景验证

至少覆盖：

- 单句修改不建立完整项目。
- “先判断”不写文件。
- “通过”只批准当前候选。
- 写入授权只作用于明确修改。
- 看似局部的样本量、统计结果、构念名、研究编号或中心结论变化会升级为影响扫描。
- 纯拼写或不改变语义的局部修改不会被不必要地升级为全文审查。
- 影响扫描优先通过状态、术语账本和文本定位完成；覆盖不足时允许读取相关章节或全文，但不能自动扩大写入范围。
- 审稿任务保持只读。
- Excel 重算先核对设计和字段。
- 字段歧义时不选择显著结果。
- 两套分析不混合参数。
- 文献只有摘要时不标记全文支持。
- 目标期刊明确时不擅自换刊。
- 局部修改不生成整篇 Word 副本。
- 结果变化生成跨章节同步清单。
- 有意暂留问题在普通轮次不重复追问。
- `WRITE_ALLOWED + RAW`、`WRITE_ALLOWED + 未重新指定的 HISTORICAL`、`REJECTED + WRITE_ALLOWED` 等非法状态组合会被拦截。
- 补丁准备失败不会改变原文件。
- 补丁写入后验证失败会恢复原文件并记录 `ROLLED_BACK`。
- 回滚遇到 Word 或 OneDrive 锁定时进入 `ROLLBACK_PENDING`，保留恢复材料并停止后续写入；解除锁定后继续原回滚。
- 恢复材料损坏或非暂时性恢复失败时进入 `ROLLBACK_FAILED`，不得报告为已恢复或继续打补丁。
- `DELIVERY_VERIFIED` 后的科学性更正必须作为新的候选重新批准，不能静默恢复旧稿。
- 总路由器、项目验证脚本和补丁模块都引用同一份 `state-consistency.md`，测试能发现任一组件使用过期或复制规则的情况。

### 14.4 真实试运行

阶段 1A 结构和行为测试通过后，用一篇真实论文进行只读试运行：形成期刊画像、审查一个章节、生成一个段落的双语候选并记录用户确认，但不修改论文文件。只有该流程的路由、证据边界和影响扫描通过验收后，才进入阶段 1B，并在论文副本上测试 Word 定点补丁、失败不改动和回滚。首次试运行不直接重算全部数据或重写全文。

实际使用发现的问题以窄范围修正进入迭代，不因单一个案堆叠通用规则。

## 15. 阶段 1A 与 1B 验收标准

阶段 1A 只有同时满足以下条件才完成：

- Plugin 和全部已创建 Skill 的结构验证通过。
- 路由引用无失效路径。
- 运行时资源加载只访问 Manifest 明确选择的路径，不执行目录遍历或模糊恢复，且受单次字符预算约束。
- 纯语言局部修改不触发全文读取；跨章节传播触发项会进入影响扫描，必要时允许读取相关章节或全文，但不会自动重写。
- “先讨论”和“通过”产生不同操作。
- 项目状态只保存用户确认的信息。
- 写作模块能按规定输出原文、修改稿和对应翻译。
- 已确认期刊可形成紧凑期刊画像。
- 证据审查适配论文类型和研究设计。
- 未经授权不修改论文文件。
- 静态验证、工具检查和试运行不被表述为作者接受或科学结论已经验证。

阶段 1B 只有同时满足以下条件才开放权威稿件写入：

- 阶段 1A 全部通过。
- 非权威测试副本上的定点替换、结构验证和视觉待检状态正确。
- 写入前能够建立短期事务恢复材料。
- 写入失败保持原文件不变，写后验证失败能够回滚。
- 回滚受文件锁阻断时能够进入等待状态、保留恢复材料并在解锁后继续；不可恢复错误能够停止为 `ROLLBACK_FAILED`。
- 非法授权、来源、证据和检查状态组合能够阻止写入。
- 三个拦截组件均使用同一份带版本的 `state-consistency.md`，不存在各自维护的非法组合副本。
- 定点补丁能够证明目标内容按预期次数被替换。
- `DELIVERY_VERIFIED` 只在所需验证完成后出现。

- 让所有心理学作者使用 Git、R、Quarto 或命令行。
- 自建 SPSS、Mplus、JASP、jamovi 或其他统计软件接口。
- 自动接受 AI、老师或审稿人的全部修改。
- 自动决定目标期刊。
- 自动公开数据或上传投稿材料。
- 自动改变原始数据或统计规格。
- 为每个小修改生成新 Word 版本。
- 在未验证前穷举全部行为实验、眼动、EEG、fMRI、心理生理、质性和元分析细则。

这些研究类型由通用多标签结构先覆盖，再根据真实使用中的明确缺口逐步扩展。

## 17. 实施前最后门槛

本设计文档经用户书面复核后，下一步使用 `writing-plans` 形成分阶段实施计划。实施计划通过后，才创建 Plugin 和 Skill 文件。实现阶段不得越过本设计规定的用户确认、来源权威、证据边界、单一正式分析源和定点补丁规则。

实施计划必须逐项落实以下收口要求：

1. 区分“影响范围读取”和“写入范围”，实现从术语账本/结构检索到相关章节或全文读取的分级影响扫描。
2. 同时测试过度升级和升级不足，尤其覆盖看似局部但会改变全文证据链的请求。
3. 将不同状态放入独立命名空间；以带机器可读 YAML frontmatter 的 `state-consistency.md` 作为单一权威规则源，由总路由器、`validate_project.py` 和 `document-patcher` 共同引用，禁止维护规则副本。
4. 将三联输出纳入 Token 预算和分块规则。
5. 阶段 1A 保持只读；通过真实稿件只读试运行后，阶段 1B 才开放文档写入。
6. 写入前建立短期事务恢复材料，验证失败自动回滚，交付验证后删除；回滚被文件锁阻断时进入 `ROLLBACK_PENDING` 并保留材料，非暂时性恢复失败进入 `ROLLBACK_FAILED` 并停止写入；后续科学性变化作为新的获批补丁处理。
