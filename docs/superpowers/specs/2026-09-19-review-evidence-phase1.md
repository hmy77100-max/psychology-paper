# Review module responsibilities and evidence verification

## Approved scope

Improve the existing evidence-audit module to help authors address publication obstacles for their target journal. The plugin specifies process, evidence provenance, context reuse and output contracts; the model performs academic reasoning and recommendations; the author chooses what to adopt. Departments are internal responsibilities, not new Skills, agents or compulsory stages.

Review-only requests take the existing short route directly to evidence-audit, including full-manuscript reviews. They do not require project initialization or journal selection. Existing project manuscript/journal profiles and shared memory are read selectively and reused. Recommendations remain separate from confirmed decisions. Review ends with feedback. A later ambiguous editing request asks full-manuscript versus targeted revision; already explicit scope is reused. Assent to advice is not an editing request.

## Responsibilities and sequence

1. Coordination: source, scope, author intent, relevant context and one integrated report. Establish now.
2. Literature and evidence verification: targeted external checking of material review questions. Build first.
3. Research and methods: design-adaptive scientific checks; distinguish reporting gaps, contradictions, limitations and author choices. Existing checks remain; deepen next.
4. Contribution and journal requirements: compare the manuscript to existing journal/profile evidence, not a second positioning workflow. Deepen after methods.
5. Revision advice organization: evidence, options, consequences and priorities. The model may recommend journals, argument changes, analyses or new experiments. Deepen after contribution review.
6. Quality review: basic source/coverage/deduplication checks now; longitudinal tracking later.

## Phase 1 behavior

The model initiates targeted browsing when an externally verifiable uncertainty could change a material recommendation. Reuse sufficient evidence already inspected; honor offline requests and unavailable tools with explicit limits. Trace original sources and exact instrument/method versions, inspect relevant content, compare applicability and competing evidence, and stop when the question is answered or further available retrieval adds no useful evidence. Never equate snippets, abstracts or failed access with full-text verification. Do not upload unpublished manuscripts to search services.

One evidence note links a review question and manuscript location to source locators, observed support, applicability, relation to the question, counterevidence, an evidence-status conclusion and access limits. Notes may remain in the conversation. No new persistent project state or literature database is required.

An optional dependency-free validator checks evidence-note structure and provenance fields only. It cannot verify URLs, read source content, evaluate applicability, choose a conclusion, score acceptance or execute searches. It must state this limit even for complete records. Missing access is a review limitation, not a reason to block all other review work.

## Maintenance boundaries

Keep canonical manifest loading and the 12,000-character budget. Add evidence resources conditionally. Do not change the journal module, writing module, analysis workflow, source manuscript or installed plugin cache. Make only narrow router clarification needed to avoid treating targeted audit lookup as the deferred literature-management module. No network service, dependency, automatic data analysis or application UI.

## Acceptance

Test offline/partial access, original versus adapted scales, legitimate uncommon usage, conflicting sources, qualitative methods, withdrawal of a suspicion, journal-context reuse, advice versus execution and explicit versus ambiguous edit scope. Structural tests do not prove model behavior; report actual sampled behavior separately. Initial delivery is a reviewable development branch, not a release or automatic merge.
