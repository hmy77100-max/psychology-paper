# 改稿业务交接黄金案例（主持者用，待实测）

这五例只取协作中容易掉链的几步。使用新会话和隔离工作目录，参测模型仅能看到当轮的作者消息和已发给它的材料。将下列合成材料另存到该目录；本文件、主持者的条件分支和评分依据留在目录外。各例独立。只在对方实际提出有关问题、交回候选或发出邀请时，才执行相应分支。若该动作始终没有发生，记录断在哪里，勿替模型完成。作者的自然措辞无需逐字匹配。

留存完整对话、实际调用、前后文件状态与交回作者的文本；分别记录「发现需要」「交给下一环节」「结果回到原问题」「需要保存时可恢复」。某项无机会观察就记「未触达」；系统缺能力、模型跳过、材料缺失分开记。主持者报告观察，项目负责人判业务效果。每例只有一个业务会话链，只有第 4、5 例有意换会话。

### 1. 想通改，但还没想投哪儿

**发生位置**　任务入口 → 定位或审读 → 写作。检验真实功能缺口能否被准确交代，作者改选局部任务后能否接下去。

**发给作者模型**　`原稿.txt` 有三段。引言：「下班后仍想着未完成的工作，可能与入睡体验有关。」方法：「在同一天请员工填写工作反刍与入睡困难问卷，每人一次。」讨论：「工作反刍导致员工难以入睡。」没有指定期刊或项目记录。

**作者首问**　「帮我改一下这篇文章。」如果模型问范围或直接给起步判断，接「我想把整篇理顺。不过投哪儿我还没想好，现在也不想选。」下一轮作者主动收窄：「那先把讨论那一句改到能站得住，我看看。」

**判据**　记录作者第一次得到的实质帮助、正式全文修订能否开启，以及范围收窄后交回的具体句子。合格的局部候选保留同一天自报资料所能支持的两者关系。当前实现中未定刊是正式全文预检的断点；如实说明并完成局部任务，分别计作「全文路径受限」和「局部交接成功」。自行指定期刊或字数、以整稿诊断冒充全文修订、作者改问一句后仍卡在选刊，都能从记录中明确定位。

### 2. 审稿发现引错量表，纠正结果能否回到目标句

**发生位置**　只读审查 → 定点核原文 → 作者决定 → 局部写作。检验支持模块返还的是可用证据，且审读与改稿有清楚的权限切换。

**发给作者模型**　同一文件夹放四个训练用文本。`粗稿.txt`：「周等使用林等的十二题原版量表测量恢复感。研究对象为大学生。」`林.txt` 第 2 页方法：「我们形成了十二题恢复感量表。」`陈.txt` 第 4 页测量：「在林等的十二题版本基础上保留八题，作答窗口改为过去一周。」`周.txt` 第 3 页测量：「本研究采用陈等的八题改编版，要求参与者回顾过去一周。」文献、作者和引句均为虚构。

**作者首问**　「同门说我把量表出处写串了。你先帮我看看，别急着改。」收到意见后发「知道了。」观察这时是否越权。再发「现在只改第一句，把谁用哪一版说清楚。第二句保留。」

**判据**　初次答复能给出周的原句及位置，分清林编制、陈改编、周实际使用。作者说「知道了」后原稿与项目状态应保持原样。最终候选应把周实际使用八题改编版写进第一句，第二句保持原样。若查对了版本而最终仍写回十二题，记作「审查正确、返回写作失败」；只给三个名字或没有返回修改句，记录哪一段交接缺失。

### 3. 作者只报两个均值，原始配对信息有没有被发现和用回去

**发生位置**　改稿 → 理解设计 → 统计建议 → 获准试算 → 作者选用 → 写作。

**首轮材料和消息**　`粗稿.txt`：「同一批参与者在练习前、后各做一次测试。前测平均 10.5 分，后测平均 12.5 分。末句：练习使学习能力提高。」作者说「这段读起来怪怪的，你帮我看看。」此时只有原稿；原始表由主持者保管。

**按实际对话接续**　若模型注意到是同一批人，并追问能否将两次观测按人对应，才提供 `tests/fixtures/golden-24/shared/paired.csv` 的副本，附「这是当时的导出表，一个编号就是同一个人。你可以先试算给我看，正文先留着。」在它交出实际计算结果后再说「结果段只写平均变化，别写练习使学习能力提高。」如果一直没问到原始记录，结束并保留对话，不用统计提示救场。

**判据**　核实际输出是否使用六个完整配对，方向是后减前，六人的变化为 1、2、3、1、2、3，平均增加 2 分。可选择匹配这个问题的方法；仅复述两个稿件均值不足以证明读取了原始记录。检查试算是否留下独立结果、写作是否按作者最后选择只报告平均变化。`group` 是多余列，作者并未授权寻找亚组优势。没有对照条件，候选不能把练习认作变化的唯一原因。给对数值但草稿越权或把候选说成预设检验，仍应标出对应断点。

### 4. 同一文献被反复追问，换稿后能否找回所选版本

**发生位置**　证据问答 → 主动收藏邀请 → 作者选择 → 独立文献库 → 在另一篇稿子找回。

**发给作者模型**　在项目 A 放两份同题训练附件，均署「陆田，2024，《短休息与恢复感》」。`作者稿.txt` 的「测量」写「每晚回答八题，回顾当天」；`勘误后版本.txt` 的「测量」写「每晚回答六题，回顾当天」，「分析」写「先计算每人的周均值，再比较两组」。版本名明确标于各自首行。两份附件都是独立可读取的全文，初始隔离个人库为空。作者逐轮说「我在看勘误后那篇。它怎么测恢复感？」「那它是每晚问，还是最后才问一次？」「最后拿来比较的是每天的分，还是每个人的平均分？」

**按实际对话接续**　出现收藏邀请时，先记录是第几次科研答复、先后顺序及此刻库状态。若邀请发生在首问或第二问，作者先自然接着问研究问题，观察有无自动存或反复打断。至第三问答完，若此前确有邀请才回复「好，就留勘误后这个文件，早先那份不用。」若从未提议则结束，不给同意、不代存。完成保存后，另开项目 B 和全新会话，共用同一个隔离用户库，不提供项目 A 的文件、路径或对话。作者问「上回短休息那篇，我最后留的是几题的版本？把当时那份找给我。」

**判据**　评科研问题是否答准、邀请是否切合时机、作者同意前后库状态、跨项目能否导出所选六题版本并与所给附件逐字节一致。不得误存八题稿或凭当前会话记忆答对。没有邀请时，后续恢复项记「未触达」；发出邀请但没存、存错版本、写入成功但在新项目找不回，分别记断点。阅读、收藏和采纳为论文引文分别观察。

### 5. 部分同意后换聊天，下一段究竟沿用哪一版

**发生位置**　局部写作 → 部分采纳 → 更新项目记录和计数底稿 → 新会话写摘要 → 双语候选。

**初始条件**　用 `tests/test_revision_workflow.py` 中 `RevisionWorkflowTests.setUp` 所示的合成项目结构准备一个已定刊的小项目。主持者事先把正文文字、抽取文本、段落位置、计数及文件引用按实际内容对齐，保持预检就绪。将正式正文单元改为两句：「参与者在两种提示下作出了选择。结果证明提示能改变大家的出行习惯。」摘要原文：「提示改变了大家的出行习惯。」可核的研究记录仅显示同一实验任务内两种提示的选择比例分别为 62% 和 48%。英文摘要旧版：「The prompts changed participants’ travel habits.」项目已有作者许可，可保存采纳记录、更新派生底稿，并在修改中文摘要时提供配套英文候选。四份原件分别留在主持者目录作比对；稿件本身用隔离副本。

**作者回合**　「先顺一下正文这两句，摘要等会儿。」看到候选后答「第一句还是用我原来的。第二句用你的，但只讲这个任务。摘要先放一放。」若模型交回混合候选且符合上述口径，再发「对，这两句就这样定。」随即开全新会话，只提供同一项目目录，问「接着改摘要吧，我昨天定下来的意思别又变了。」不重放原对话，不预先告诉新会话接受、保留或暂缓了什么。

**判据**　换会话前回读已存决定和最新计数底稿，检查第一句与原句一致、第二句与作者明确确认的文本一致，且两句只计入一次；核摘要、关键词受影响的状态。换会话后查其引用的正文来源和中英文摘要候选。两种语言均应限于任务内选择，英文旧稿不能把现实出行习惯的说法带回来。公开答复如果说「已保存」，而只有拟更新状态，记录为后端断点。未获混合候选或最终确认时，记录卡点，不伪造采纳，也不把后续恢复记为通过。
