# Full-manuscript writing

Run revision_check.py preflight against actual project/profile/baseline files. Reuse the author's confirmed contribution, scope and outline rather than requesting them again. Work in reviewable logical units; the author's chosen sequence controls their order. A suggested body/abstract/keywords sequence can reduce rework but is not a prerequisite for drafting or approving a particular unit.

Use `revision_check.py stage --project-root ROOT --section SECTION` when dependency information is useful; its stage_notes identify later synchronization, not an order gate. The optional --explicit-stage-request records the author's actual instruction without approving other units. No extra author approval or per-unit stage call is needed solely to satisfy a default order.

Use project mode with the current source, applicable confirmed journal requirements and effective decisions. Resolve material evidence conflicts using focused review; completed positioning or audit work need not restart. Preserve the current authoritative mainline and each unit's actual adoption state.

Keep deliveries reviewable within the available budget, preserving complete source comparison for the selected units. Track author decisions in existing state. Adopted body changes refresh the mainline count and invalidate affected abstract/keywords versions, not all previously approved body prose. An early abstract remains an abstract of the inspected source, not proof that every body unit is approved.
