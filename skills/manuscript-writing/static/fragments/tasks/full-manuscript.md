# Full-manuscript writing

Before drafting, run revision_check.py preflight against actual project/profile/baseline files; a budget arithmetic pass or a claimed completed preflight is insufficient. Agree on contribution and outline direction with the author. Use argument-complete logical units rather than physical layout paragraphs. Body changes require refreshing the adopted mainline count and invalidating dependent abstract/keywords. Explicit author sequence overrides do not imply adoption of unfinished text.

Before each unit, run `revision_check.py stage --project-root ROOT --section SECTION`. It checks the default dependency order before drafting, not merely after an abstract is delivered. Record explicit exceptions with --explicit-stage-request and carry that exact author instruction into the decision record.

Use only in project mode after journal positioning and evidence audit. The default revision sequence is `Body sections → Abstract → Keywords`; revise the title when the user requests it or when the submission framing is finalized. Process each body section, the abstract, and the keywords as separate approved units. Carry forward only the current authoritative mainline and approved constraints.

Never output the entire source, full revision, and full translation at once. Identify logical units by argumentative function and closure, not Word paragraph breaks; one unit may span several paragraphs. Track units and author decisions in state. Body changes invalidate affected abstract/keywords versions, not all previously approved body prose.
