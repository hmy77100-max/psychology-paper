# Bounded execution and reuse

Reduce repeated loading, unnecessary dispatch and empty polling—not the author's full original → revision → explanation, source verification or numerical checks.

- Normal prose revision stays with the primary agent. Arrange independent specialist review only when a concrete numeric/evidence conflict or cross-section dependency warrants it and the environment permits delegation. No fixed writer/checker/cross-section team for each paragraph.
- Prefer completion events or one bounded wait to frequent status queries. Unchanged status is expected; do not create repeated model turns solely to ask whether it changed. Keep the user informed when work or decisions change.
- Plan loads from exact manifest selectors. Use load_skill_resources.py --list-selectors for valid keys and --describe for full per-resource costs/hashes. No guessed aliases, recursive path discovery, raised budget or truncated instruction loading. Read a chosen resource fully. If a legitimate set exceeds 12,000 characters, stop that invocation and report the full total, first overflow and selected set. Diagnose duplicates/conditional scope before proposing a new stage; do not retry slightly different combinations until one happens to fit.
- Reuse fully read instructions within the same task when the manifest/resource hashes match. The loader still validates actual files; --describe is a cost/version plan, not a declaration that instructions have been read. A changed version or lost context requires loading the needed instructions again.
- Extract the authoritative original once into a derived UTF-8 baseline with original-file SHA256, extraction SHA256, extraction method/version, paragraph IDs, tables/cells and page locators where available. Do not fabricate pages absent from extraction. Preserve the original. Reuse the verified baseline for the current complete logical unit, necessary neighbors and linked evidence. Changed source/hash, disputed extraction or a scientific conflict requires returning to the original.
- External browsers/search/reference tools are implementation tools inside the workflow, not independent authorities. Use only available tools, minimize transmitted private content, record exact source identity/access depth and unresolved errors, and preserve approval boundaries. Never assume a result is true because a connector returned it.
- Check delivery format before presenting a candidate. Keep evidence verification, mechanical validation and long-run agent behavior validation separate in reports. A synthetic test passing is not proof that execution drift can never recur.
