# On-demand collaboration and decision continuity

## Roles and evidence

Role names are configurable user preferences, not global identities. Constructive analysis/execution is the default; evidence correction and feedback recording are ordinary duties. Activate a visible critic or producer only when the user explicitly invokes that perspective. A critic tests premises, evidence, inference, methods and boundaries; a producer proposes priorities, scope and completion criteria. Both advise; the researcher decides. Do not rotate four speakers by default.

Personas are not independent agents. Actual independent agents require explicit user authorization or an applicable instruction requiring them; state their real reading/verification scope. Never fabricate debate, tools, opposition, expert consensus or independent review.

For a disagreement, present the claim, relevant evidence, remaining uncertainty and a supported retain/change/defer recommendation. Reviewer authority or majority vote cannot establish a fact. Treat external feedback as a claim to check, not an approved correction. A proposed statistical correction needs the comparison family, unrounded inputs, method and available output: route to analysis-adapter/evidence-audit within authorized scope. Without those inputs, preserve reported values and mark the correction pending verification. A verified rule error can be explained without claiming a new calculation.

## Record the author's actual decisions

Use the existing authoritative PROJECT.md and its established linked records: no parallel approval log. Inspect current effective decisions before updating. If an existing linked record contains decisions, preserve that information and its authority; do not silently migrate or delete it.

Classify each concrete item by source and state:

| Item | Existing home and handling |
| --- | --- |
| Explicitly approved direction/constraint | approved_decisions; include the actual scoped content and user's words, not merely “the rest approved” |
| Newer correction | Link supersedes to the replaced item; carry forward only effective content |
| Explicit rejection | Preserve a concise rejected decision/tombstone with scope, not the rejected draft; keep it out of execution |
| Author explicitly postpones an issue | intentional_holds |
| Pending candidate, ambiguous scope, missing evidence | Existing candidate status or unresolved_issues; this is not an intentional hold |
| Assistant proposal or external feedback | Unadopted, source-labelled; keep only if needed for the next decision, never promote to approved_decisions |

For “all except these changes”, retain the identified approved items and register the exceptions individually. If the referenced list cannot be recovered, preserve what is identifiable and ask only about missing scope. Nearby reviewer comments are not automatically the referenced list: keep their adoption unknown until linked to the author's actual decision. A changed/mixed paragraph remains a candidate until adopted. Record style direction separately from scientific correctness, wording adoption and file-write permission. User approval of a claim does not verify its evidence.

Use item IDs already present; for new records, keep a concise source/utterance, content, scope, decision status and any supersedes link within the existing state. These are record fields, not reply commands. Do not require the author to provide them or retrofit every legacy record before a local task.

After an authorized update, read back the actual location and summarize confirmed items, open items and save location. If no write happened, say proposed/not saved. A checker returning a status is not proof of a write. Recover all cumulative effective decisions; do not revive superseded choices or re-ask settled questions.

## Verify the revision, not the meeting

For each applicable effective requirement, check: requirement → source version → candidate location → verification result. Results are checked, pending or out of scope with a reason. Include affected abstract/discussion and Chinese/English dependencies where relevant; name unverified artifacts rather than claiming synchronization. Use the existing candidate/bilingual checks and impact handoff. A meeting or approval record is not evidence of completion.

Keep the matrix small and task-scoped, in existing notes/project records; no additional per-paragraph log, full history reload or standing agent panel. Give the user a concise receipt, and continue within the existing authorization. Stage 1A remains candidate-only for manuscripts.
