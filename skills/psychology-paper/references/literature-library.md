# Personal literature and previous highlights

Use this resource when the author wants to keep or recall a reading. Resolve the scripts below from the plugin root, even when working on a different manuscript.

## Keep and recall

- When results overlap, run `scripts/literature_library.py compare --input A.json --input B.json` on existing UTF-8 query results. Compare locally before loading long lists into the conversation. Show each paper once with its sources; keep conflicting records and related versions identifiable. A source failure leaves its coverage unknown.
- When the author chooses a record, use `save --input FILE --pick N` on the detailed response (or stdin with `--input -`). Source rows start at 1. Fetch details if only a preview is available. Add a requested `--tag`. After saving, state the library location and what this save kept: citation, attachment link or recoverable file. For `metadata_conflict`, show the disagreement and check the source.
- Search across manuscripts with `literature_library.py find "term"` (purpose, note, title, author, DOI or locator). If needed, continue with `--offset` using the returned `next_offset`. Use `show ID` to retrieve versions, sources, attachments and reading notes. The default is `~/PsychologyPaper/literature.sqlite3`; a read-only lookup can be the first action in a new chat. `--library PATH` before the command selects another personal database.
- Save actual reading details with `save --id ID --read --version "accepted manuscript" --attachment PATH --locator "Table 2" --note "..."`. A normalized DOI identifies a bibliographic record; show the particular version and attachment that carry the reading. Keep distinct preprint and published DOIs and their documented relation. If the tool returns a possible title match, show the choices and let the author identify the same or a separate work. An ordinary attachment reference points to the author's file.
- If the author asks to keep the file itself, add `--store-file` to that save. The personal database then retains the exact bytes even if the PDF is replaced or moved. Recover it with `export-attachment ID --output NEW_PATH`; for several files under one DOI use the chosen reading entry's `--sha256 HASH`. The destination must be a new file. To record later reading of the stored copy, use `save --id ID --sha256 HASH --read --locator "..."`.
- Saving a paper for later does not mark it read. When the author chooses to cite it, pass the specific version and locator to the existing manuscript evidence workflow.
- To compare an external candidate with the author's reading, run `scripts/literature_library.py reading-status --doi DOI` locally. Keep the database that surfaced the work and the local reading status as separate facts. Report an explicit reading with its own version or attachment; an unlabelled trace leaves the version unspecified. A saved-only record, a missing record, and an unavailable library carry different meanings. Without a DOI, leave the match unresolved. No reading data goes into a public query.

## “Find the sentence I highlighted”

Use `scripts/zotero_read.py` with the author's running Zotero desktop app and local communication enabled. The reader uses HTTP GET on this computer and requires no cloud API key.

1. Narrow by a known title or author with `papers --query "term"`, or use `papers --doi DOI`. If the author remembers a collection, use `collections` and `papers --collection KEY`. For a local group library add `--group ID`. Use the available next page when a bounded result list is incomplete.
2. Use `highlights --paper KEY`, optionally adding `--query "remembered words"`. When only the collection and a phrase are known, use `highlights --collection KEY --query "phrase"` (five papers per batch). Use `next_start` for more annotations in this batch, then `next_paper_start` as `--paper-start` for the next batch. A match in a comment can find the note even if the paper uses different words. Preserve each PDF attachment as a separate version. If multiple readings fit, show enough title, year, attachment and page details for the author to choose.
3. Show the selected text verbatim, the author's comment separately, the actual PDF attachment and a clickable `open_url`. Identify the physical PDF page and Zotero's page label as supplied; a printed page number needs confirmation from the document. For an area or note without selected text, show its available content and location. This lookup sees annotations exposed by Zotero. A mark embedded only in an external PDF may need importing in Zotero before it appears. Keep the lookup local; copying private notes to the personal library is a separate author request.
